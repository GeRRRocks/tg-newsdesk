# TG_NEWS_BOT

Telegram-бот для автопостинга новостей в группу с ручной модерацией. Бот сам
собирает новости из источников, переписывает их в короткий пост через нейросеть
(Claude, GPT, Gemini или DeepSeek — на выбор) и присылает черновик
администраторам в личку — пост уходит в группу только после нажатия
«Опубликовать».

По умолчанию настроен на автомобильные новости, но тематика задаётся текстом
промпта: источники тематически нейтральны, так что бот подходит для канала на
любую тему.

## Как это работает

1. По расписанию (или по кнопке «⚡ Сгенерировать») бот опрашивает включённые
   источники и берёт самую свежую новость, которой ещё не было.
2. Нейросеть переписывает её в пост по системному промпту.
3. Черновик с кнопками приходит каждому администратору в личку: его можно
   опубликовать, отклонить, попросить другой вариант или заменить своим
   текстом.
4. После подтверждения пост публикуется в целевую группу — в конкретный топик,
   если он задан. У остальных администраторов кнопки под черновиком пропадают.
5. Черновик, на который никто не ответил за сутки, закрывается сам.

Бот полностью приватный: отвечает только администраторам из `ADMIN_CHAT_IDS`,
сообщения и нажатия всех остальных молча игнорируются.

## Быстрый старт (Docker)

Нужен только Docker с плагином compose. Бот, PostgreSQL и резервное
копирование работают в трёх контейнерах; база не публикует порты и живёт в изолированной сети без выхода в
интернет, данные хранятся в именованном томе `pgdata`.

```bash
git clone https://github.com/GeRRRocks/TG_NEWS_BOT.git
cd TG_NEWS_BOT
cp .env.example .env             # заполнить значения, см. ниже
docker compose up -d --build
```

Что вписать в `.env` и где это взять — в разделах
[«Настройка Telegram»](#настройка-telegram),
[«Нейросеть»](#нейросеть) и
[«Переменные окружения»](#переменные-окружения). Пароль базы придумывать не
нужно, сгенерируй: `openssl rand -hex 24`.

Управление — через `make` (список команд: `make` без аргументов):

```bash
make status      # состояние контейнеров
make logs        # логи бота в реальном времени
make restart     # перезапустить бота, в том числе после правки .env
make deploy      # пересобрать образ и перезапустить бота после изменения кода
make update      # забрать свежий код из git и развернуть
make backup      # снять дамп базы сейчас (в backups/ и в S3, если настроен)
make restore FILE=backups/<файл>   # восстановить базу из дампа
make psql        # консоль PostgreSQL
make down        # остановить всё (данные в томе сохраняются)
```

Это короткие обёртки над `docker compose`, им можно пользоваться и напрямую.
После правки `.env` нужен `make restart` (или `docker compose up -d`):
`docker compose restart` переменные не перечитывает.

## Настройка Telegram

1. Создать бота через [@BotFather](https://t.me/BotFather), токен вписать в
   `BOT_TOKEN`.
2. Узнать chat_id каждого администратора (например, через
   [@userinfobot](https://t.me/userinfobot)) и вписать их через запятую в
   `ADMIN_CHAT_IDS`. Каждый администратор должен сам написать боту `/start` в
   личку — иначе бот не сможет присылать ему черновики.
3. В целевой группе включить темы: **Settings → Topics**.
4. Добавить бота в группу и выдать права администратора: **Post Messages** и
   **Manage Topics**. Без второго публикация в закрытый топик падает с ошибкой
   Telegram `TOPIC_CLOSED`.
5. В `TARGET_GROUP_CHAT_ID` временно вписать свой chat_id (значение
   обязательно, без него бот не запустится) и запустить бота.
6. Отправить `/get_topic_id` прямо внутри нужного топика группы (не в General и
   не в личку) — бот ответит готовыми строками `TARGET_GROUP_CHAT_ID` и
   `TARGET_TOPIC_ID`.
7. Вписать их в `.env` и применить: `make restart`.

Если администратор пишет в группе не от личного аккаунта, а анонимно или от
имени бизнес-аккаунта, в `ADMIN_CHAT_IDS` нужен id именно того аккаунта, от
которого реально приходят сообщения — иначе бот их проигнорирует. Проверить
можно по `from_user` в логах бота.

## Переменные окружения

Все секреты и идентификаторы задаются только в `.env` (шаблон —
`.env.example`), в коде ничего не зашито. Файл `.env` в git не попадает.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `AI_PROVIDER` | нейросеть по умолчанию: `anthropic`, `openai`, `gemini` или `deepseek`; если не задана — `anthropic` |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `DEEPSEEK_API_KEY` | ключи API; обязателен только ключ нейросети из `AI_PROVIDER` |
| `AI_MODEL` | модель для нейросети из `AI_PROVIDER`; можно не задавать |
| `ADMIN_CHAT_IDS` | chat_id администраторов через запятую — черновики приходят всем |
| `TARGET_GROUP_CHAT_ID` | chat_id целевой группы |
| `TARGET_TOPIC_ID` | id топика для публикации; можно не задавать |
| `TIMEZONE` | таймзона расписания (IANA), по умолчанию `Europe/Moscow` |
| `DRAFT_INTERVAL_MINUTES` | начальный интервал автогенерации, по умолчанию 60 |
| `DRAFT_EXPIRE_HOURS` | через сколько часов без ответа черновик закрывается сам; по умолчанию 24, `0` — никогда |
| `BOT_TOPIC` | тематика для промпта по умолчанию |
| `BACKUP_TIME`, `BACKUP_KEEP_DAYS` | время ежедневного дампа (по умолчанию `03:30`) и срок хранения локальных копий в днях (14) |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_PREFIX` | хранилище для копий базы, см. [«Резервные копии»](#резервные-копии); можно не задавать |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | учётные данные контейнера с PostgreSQL (только Docker) |
| `DATABASE_URL` | строка подключения к PostgreSQL (только запуск без Docker) |

В Docker `DATABASE_URL` из `.env` игнорируется: compose собирает его сам из
`POSTGRES_*` и адреса сервиса `db`.

`DRAFT_INTERVAL_MINUTES` и `BOT_TOPIC` — только стартовые значения. После
первого изменения через меню действуют настройки из базы.

## Нейросеть

Посты может писать одна из четырёх нейросетей. Ключи задаются в `.env`,
а переключаться между ними можно прямо из меню бота.

| `AI_PROVIDER` | Нейросеть | Переменная с ключом | Где взять ключ | Модель по умолчанию |
|---|---|---|---|---|
| `anthropic` | Claude | `ANTHROPIC_API_KEY` | [console.anthropic.com](https://console.anthropic.com) | `claude-opus-5` |
| `openai` | GPT | `OPENAI_API_KEY` | [platform.openai.com](https://platform.openai.com) | `gpt-5.4-mini` |
| `gemini` | Gemini | `GEMINI_API_KEY` | [aistudio.google.com](https://aistudio.google.com) | `gemini-3.8-flash` |
| `deepseek` | DeepSeek | `DEEPSEEK_API_KEY` | [platform.deepseek.com](https://platform.deepseek.com) | `deepseek-flash` |

**Настройка в `.env`.** Минимум — одна нейросеть: её название в
`AI_PROVIDER` и её ключ. Без этого ключа бот не запустится и напишет в логах,
какой переменной не хватает. Остальные ключи можно оставить пустыми или
вписать сразу несколько — тогда эти нейросети станут доступны в меню.

```bash
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=...             # ключ нейросети по умолчанию — обязателен
ANTHROPIC_API_KEY=...            # необязательно: вторая нейросеть для меню
```

**Переключение в боте.** Кнопка «🤖 Нейросеть» показывает, кто пишет посты
сейчас и на какой модели, и список всех четырёх нейросетей. Текущая отмечена
✅, нейросети без ключа — 🔒. Переключение срабатывает сразу, без перезапуска:
следующий черновик пишет уже выбранная нейросеть. Сам ключ через бота ввести
нельзя — чтобы открыть нейросеть с замком, впиши её ключ в `.env` и выполни
`make restart`.

Выбор из меню хранится в базе и важнее `AI_PROVIDER`. Значение из `.env`
используется, пока в меню ничего не выбирали, и если ключ выбранной нейросети
из `.env` убрали.

**Модель.** `AI_MODEL` заменяет модель по умолчанию только у нейросети из
`AI_PROVIDER`; остальные работают на своей модели из таблицы. Названия моделей
у провайдеров меняются: если модель по умолчанию перестала работать, в логах
будет ответ провайдера с ошибкой — укажи актуальную модель в `AI_MODEL`.

Системный промпт общий для всех нейросетей. Какая нейросеть и модель активны,
видно в логах при старте бота.

## Управление ботом

Всё управление — через кнопки, `/start` открывает главное меню:

| Кнопка | Что делает |
|---|---|
| 📋 Источники | список источников и статистика черновиков; тап открывает карточку с «Выключить/Включить» и «Удалить» |
| ➕ Добавить | мастер: адрес сайта, фида или Telegram-канала → бот сам определяет тип → название или «Пропустить» |
| ⚡ Сгенерировать | собрать новость и сгенерировать черновик сразу, не дожидаясь расписания |
| ⏱ Расписание | режим и параметры автогенерации, см. ниже |
| 🏷 Промт | посмотреть, изменить или сбросить системный промпт нейросети |
| 🤖 Нейросеть | какая нейросеть пишет посты; переключение между теми, чьи ключи есть в `.env`, см. [«Нейросеть»](#нейросеть) |
| 🚫 Фильтр | стоп-слова и обязательные слова для новостей, см. [«Фильтр по словам»](#фильтр-по-словам) |
| 🏓 Пинг | проверка, что бот жив |

Единственная команда, которую нельзя заменить кнопкой, — `/get_topic_id`.

### Черновик

Под каждым черновиком четыре кнопки:

| Кнопка | Что делает |
|---|---|
| ✅ Опубликовать | отправляет пост в группу |
| ❌ Отклонить | закрывает черновик, эта новость больше не предлагается |
| 🔄 Другой вариант | нейросеть заново пишет текст той же новости |
| ✏️ Править | бот просит прислать свой текст, он заменяет сгенерированный |

После «Другого варианта» и «Править» старые карточки у всех администраторов
закрываются с пометкой, и всем приходит новая — её и нужно публиковать. Свой
текст публикуется как есть, без разметки.

Черновик без ответа закрывается через `DRAFT_EXPIRE_HOURS` часов (по
умолчанию 24): кнопки пропадают, под карточкой появляется пометка. В
статистике такие черновики считаются отдельно — «Истекло», а не «Отклонено».

### Расписание

Два режима, переключаются в меню «⏱ Расписание» и применяются сразу, без
перезапуска:

- **⏱ Интервал** — раз в N минут: готовые варианты или своё число.
- **📅 Дни и время** — выбранные дни недели и одно или несколько времён в
  сутки (например, 09:00 и 18:00), общих для всех выбранных дней. Время — в
  таймзоне из `TIMEZONE`. Пока не выбраны хотя бы один день и одно время,
  продолжает работать интервал.

### Источники

Тип источника бот определяет сам по присланному адресу. Можно прислать
главную страницу сайта: бот проверит, не фид ли это, поищет RSS, объявленный
на странице, затем типовые адреса фидов (`/rss`, `/feed`, `/rss.xml` и т. п.)
и, если нашёл, сохранит источник с адресом фида. Если RSS нет, а на странице
есть ссылки на статьи, источник добавится как HTML. Если не нашлось ничего,
бот предупредит и предложит выбрать тип вручную.

Типы:

- **RSS** — адрес RSS/Atom-фида.
- **HTML** — обычная страница со списком новостей, для сайтов без RSS. Бот сам
  находит на ней ссылки, похожие на статьи, и берёт заголовок, описание и
  картинку из og-тегов каждой статьи. Способ универсальный и под конкретный
  сайт не настраивается, поэтому качество зависит от вёрстки сайта.
- **Telegram-канал** — публичный канал. В мастере достаточно прислать `@имя`
  или ссылку `t.me/имя`, тип определится сам. Бот читает веб-версию канала
  (`t.me/s/имя`) — последние примерно 20 постов, без входа в Telegram и без
  добавления бота в канал. Заголовком становится первая строка поста, в
  черновик попадает ссылка на сам пост. Закрытые каналы и каналы, у которых
  веб-просмотр отключён, так не читаются — такой источник попадёт в
  уведомление о сбоях. Рекламные посты канала бот не отличает от новостей:
  их отсекает фильтр по словам или кнопка «Отклонить».

В списке источников виден общий итог по черновикам, в карточке источника —
его собственный: сколько опубликовано, отклонено, ждёт решения и истекло. По
этим цифрам видно, какой источник стоит выключить.

Бот ходит только по публичным адресам (`http`/`https`) и не читает ответы
больше 3 МБ — такие источники пропускаются с предупреждением в логах.

### Фильтр по словам

Кнопка «🚫 Фильтр» задаёт два списка слов или фраз, общих для всех источников:

- **Стоп-слова** — новость, где есть любое из них, пропускается.
- **Обязательные слова** — если список не пуст, берутся только новости, где
  есть хотя бы одно из них.

Слова присылаются одним сообщением через запятую и заменяют прежний список.
Ищется вхождение в заголовок и анонс без учёта регистра: «кроссовер» поймает
и «кроссоверы». Фильтр срабатывает до обращения к нейросети, поэтому
отсеянные новости ничего не стоят.

### Уведомления о сбоях

Бот сам пишет администраторам, если что-то сломалось:

- нейросеть не смогла написать черновик по расписанию — одно сообщение на
  серию сбоев и ещё одно, когда генерация восстановится;
- источник три запуска подряд не открывается или не отдаёт ни одной новости;
- в боте случилась неожиданная ошибка — при нажатии кнопки или в задаче по
  расписанию. Одинаковые ошибки повторяются в сообщениях не чаще раза в
  10 минут; подробности — в `make logs`;
- резервная копия базы не снялась или не отправилась в S3.

Счётчики сбоев сбрасываются при перезапуске бота. Если не работает сам бот
или сервер, сообщений не будет — за этим нужно следить отдельно.

### Тематика и промпт

Тема задаётся только системным промптом нейросети:

- **`BOT_TOPIC` в `.env`** — подставляется в промпт по умолчанию;
- **кнопка «🏷 Промт»** — полная замена текста промпта на лету. Там же можно
  задать длину поста, тон, формат и что угодно ещё.

Чтобы перевести бота на другую тему, достаточно поменять промпт и набор
источников — код трогать не нужно. Промпт не зависит от выбранной нейросети.

## Резервные копии

Контейнер `backup` каждый день в `BACKUP_TIME` снимает дамп базы в папку
`backups/` рядом с проектом (сжатый файл `tg_news_bot_<дата>_<время>.sql.gz`).
Локальные копии старше `BACKUP_KEEP_DAYS` дней удаляются.

**Отправка в S3.** Чтобы копии уходили ещё и за пределы сервера, впиши в
`.env` параметры S3-совместимого хранилища и выполни `make up`:

```bash
S3_ENDPOINT=https://storage.yandexcloud.net   # адрес хранилища, без имени бакета
S3_REGION=ru-central1
S3_BUCKET=my-bot-backups
S3_ACCESS_KEY=...
S3_SECRET_KEY=...
S3_PREFIX=tg-news-bot/                        # необязательно
```

Ключу достаточно права на запись объектов в этот бакет. Проверить настройку:
`make backup` — в выводе должна быть строка «отправлено в S3». Из S3 скрипт
ничего не удаляет: срок хранения там задаётся правилом жизненного цикла в
настройках бакета. Если копия не снялась или не отправилась, контейнер
`backup` пишет об этом администраторам в Telegram; журнал — `make logs-backup`.

**Восстановление.**

```bash
make restore FILE=backups/tg_news_bot_2026-10-01_033000.sql.gz
```

Команда спросит подтверждение, остановит бота, сохранит текущую базу отдельным
дампом, заменит её содержимым файла и запустит бота. Чтобы только заглянуть в
дамп, не трогая рабочую базу, его можно развернуть в отдельную:

```bash
RESTORE_DB=check make restore FILE=backups/<файл>
```

**Откат кода.** Черновики со статусом «истёк» понимает только код начиная с
коммита `496bec1`. Откатываясь на более раннюю версию, сначала переведи их в
«отклонён»: в `make psql` выполни
`UPDATE posted_news SET status = 'REJECTED' WHERE status = 'EXPIRED';`

## Установка без Docker

### Автоматически (Ubuntu, systemd)

Скрипт ставит Python и PostgreSQL, создаёт venv, базу и `.env` (нейросеть,
её ключ и токены спрашивает в диалоге) и регистрирует systemd-сервис:

```bash
git clone https://github.com/GeRRRocks/TG_NEWS_BOT.git
cd TG_NEWS_BOT
sudo bash scripts/install.sh
```

```bash
systemctl status tg-news-bot     # статус
journalctl -u tg-news-bot -f     # логи в реальном времени
systemctl restart tg-news-bot    # перезапуск, в том числе после правки .env
```

После установки выполни шаги 6–7 из раздела
[«Настройка Telegram»](#настройка-telegram) и перезапусти сервис.

### Вручную

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -c constraints.txt
cp .env.example .env             # заполнить значения, включая DATABASE_URL
python main.py
```

Нужен работающий PostgreSQL; таблицы создаются автоматически при первом
запуске.

### Перенос в Docker

Чтобы перевести уже работающую установку (процесс `python main.py` и
PostgreSQL на хосте) в Docker, останови старый процесс бота и запусти:

```bash
bash scripts/docker-migrate.sh
```

Скрипт снимает дамп старой базы, восстанавливает его в контейнер, сверяет
количество строк по таблицам и только после этого запускает бота. Старая база
не изменяется.

## Устройство проекта

Стек: Python 3.12, [aiogram 3](https://docs.aiogram.dev/), SQLAlchemy 2 +
asyncpg (PostgreSQL), APScheduler, httpx, feedparser, BeautifulSoup4, Anthropic
Python SDK (остальные нейросети вызываются по HTTP через httpx).

```
main.py                 # точка входа
bot/
  config.py             # настройки из .env (Pydantic Settings)
  filters/
    admin.py            # IsAdmin — пропускает только администраторов
  handlers/
    base.py             # /start, главное меню, /get_topic_id
    sources.py          # список, добавление, включение и удаление источников
    generate.py         # кнопка «Сгенерировать»
    schedule.py         # меню расписания
    prompt.py           # меню промпта
    ai.py               # меню выбора нейросети
    news_filter.py      # меню фильтра по словам
    moderation.py       # карточка черновика: публикация, правка, автозакрытие
    errors.py           # перехват неожиданных ошибок
  services/
    news.py             # загрузка источников, разбор RSS, выбор свежей новости
    scraper.py          # сбор новостей с HTML-страниц
    source_detect.py    # определение типа источника по адресу, поиск RSS
    telegram_channel.py # сбор постов публичных Telegram-каналов
    ai.py               # рерайт новости через выбранную нейросеть
    news_filter.py      # фильтр новостей по словам
    alerts.py           # сообщения администраторам о сбоях
    scheduler.py        # расписание и цикл «собрать → сгенерировать → отправить»
  db/
    models.py           # Source, PostedNews, Draft, DraftNotification, BotSetting, Topic
    session.py          # async engine и сессии
Dockerfile              # образ бота
Dockerfile.backup       # образ резервного копирования
docker-compose.yml      # бот + PostgreSQL + резервные копии
Makefile                # короткие команды управления (make help)
requirements.txt        # прямые зависимости
constraints.txt         # точные версии всех пакетов, по ним собирается образ
scripts/
  install.sh            # установка без Docker (systemd)
  docker-migrate.sh     # перенос существующей установки в Docker
  backup.sh             # дамп базы и отправка в S3 (работает в контейнере backup)
  restore.sh            # восстановление базы из дампа
```

Таблицы создаются при старте бота, миграций нет: изменения схемы вносятся в
`bot/db/models.py`, а новые колонки существующих таблиц — ещё и в
`init_models()` (`bot/db/session.py`).
